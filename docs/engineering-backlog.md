# Engineering backlog

Created October 28, 2026 from [the codebase review](codebase-review-2026-10-28.md). This is the team's working queue. All items start **Open / Unassigned**; priorities reflect the reviewed snapshot, not a claim that subsequently edited code still has every defect. Recheck the affected code when starting an item. Previously fixed findings from the October 5 review are excluded.

## How to use this backlog

- **P0 — stop-use blocker:** confirmed immediate risk of unintended/damaging movement or inability to operate safely. None assigned solely from source review. Promote hardware/reference items to P0 if a physical check demonstrates that risk.
- **P1 — correctness/reliability:** address before depending on the affected mechanism, localization, simulation, or match feature. A P1 in unused functionality does not block unrelated work.
- **P2 — framework/operational improvement:** address during the offseason and before expanding or reusing the affected API next season.
- **P3 — cleanup/polish:** schedule after correctness and contract work; combine related cleanup with nearby changes.

IDs remain stable when priorities or ordering change. Dependencies below are prerequisites for the final implementation; investigation and small protective fixes can proceed sooner. “Hardware” means physical facts or acceptance checks are needed, not that the issue is proven on the robot. Complete an item only after its acceptance criteria are met; track tests in the same change where practical. An item can be resolved by removing an unused feature rather than implementing it.

## Recommended work sequence

Priority sets urgency; this sequence accounts for dependencies and keeps changes reviewable.

1. **Establish evidence:** ROB-014 test foundation; hardware facts for ROB-007/008/009/011; ROB-013 logging and ROB-036 version alignment. These can progress alongside the first fixes.
2. **Fix narrow correctness defects:** ROB-001, ROB-010, ROB-002/016, ROB-006. Add a regression test with each change.
3. **Make output and lifecycle contracts reliable:** ROB-018/012, ROB-017/005, ROB-020/004, ROB-023. Complete physical reference/unit fixes before enabling dependent actions.
4. **Make shooting reliable:** ROB-024/025, ROB-015/027, ROB-003, ROB-031. A protective feed gate can land earlier; finish its readiness contract after units/reference/solution state are trustworthy.
5. **Protect match operation and integration:** ROB-030/039, ROB-033, ROB-035, then the remaining utilities and operating-policy items. Promote ROB-026/032 if their affected paths are active.
6. **Prepare for reuse:** ROB-019/021, resolve ROB-022 replay scope, ROB-028/029/040, and ROB-041. Deliver incremental refactors with existing behavior preserved.
7. **Polish in context:** ROB-042–048, avoiding unrelated formatting churn in functional changes.
